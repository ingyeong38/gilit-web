# SFR-006 소요시간 그래프 — 프론트엔드 인계

담당: 양해민 / 백엔드 담당: 주인경. 2026-11-14.

## 브랜치와 작업 폴더

원래 폴더의 haemin/login에는 로그인 미커밋 변경사항과 backend/data/가 있어 그대로 보존했다.
git fetch origin main 후 origin/main(ff15777)에서 haemin/duration-graph를 새로 만들었다.
작업 폴더는 /private/tmp/gilit-duration-graph이다. 원래 폴더는 계속 haemin/login이다.
commit, push, merge, 배포는 하지 않았다. /private/tmp는 임시 위치이므로 영구 보관용 폴더로 착각하지 않는다.
VS Code의 파일 → 새 창 → 폴더 열기에서 이 작업 폴더를 열면 새 브랜치가 표시된다.

## 기존 구현과 차이

기존에도 SVG 선과 경로 선택 코드는 있었다. 다만 X축이 배열 인덱스 기준이라
불규칙한 시간 간격을 표현하지 못했고, Y축 숫자 눈금·터치·키보드·데이터 검증이 없었다.
실제 모드에서는 그래프가 숨겨졌으며 그래프 요청 실패가 경로 결과 전체를 막을 수 있었다.

변경 후에는 기존 SVG와 카드/지도 선택 흐름을 재사용하며:

- X축은 timestamp 차이에 비례하고 Y축에 분 단위 숫자를 표시한다.
- 권장 출발은 실제 시간 위치의 점선과 텍스트로 강조한다. 범위 밖이면 별도로 안내한다.
- 같은 선택 인덱스의 지도와 그래프에 같은 경로 ID 및 색상을 사용한다.
- 마우스 hover, 터치 클릭, Tab 진입과 방향키/Home/End로 데이터를 확인한다.
- 그래프 아래 고정 읽기 영역과 펼칠 수 있는 데이터 표를 제공한다.
- 예시는 실제 교통 예측이 아니라는 문구를 표시한다.
- 로딩·연동 대기·데이터 없음·실패를 구분하며 그래프가 실패해도 지도/카드는 유지한다.
- 실제 API 응답 제한은 10초다. 한 검색당 전체 그래프를 한 번만 조회하고 카드 전환 시 재요청하지 않는다.

데이터 시각을 검증한 뒤 정렬한다. 음수/비수치 소요시간과 잘못된 날짜는 제외하고
중복 시각은 마지막 유효 값을 사용한다. 중복 routeId는 모호하므로 그 ID 전체를 제외한다.
다른 경로 ID나 숫자 ID를 문자열 ID에 임의 매칭하지 않는다.
시각에 시간대가 없으면 KST로 해석하며, Z/offset이 있으면 실제 시각으로 계산하고 KST로 표시한다.
1개 데이터는 점으로 표시한다. 작은 화면은 그래프 내부 가로 스크롤로 눈금 잘림을 피한다.
방문자/통계 차트는 변경하지 않았다.

## API 구현 여부와 주인경 팀원 요청

현재 docs/api-spec.md와 backend/app/api/를 확인한 결과 GET /api/routes/graph는 미구현이다.
기본 GRAPH_API_ENABLED=false이며, 실제 경로 모드에서는 요청하지 않고 연동 대기를 표시한다.
API를 준비한 뒤 frontend/js/config.js에서 이 값만 true로 바꾸면 호출할 수 있다.
서버 구현·보안·DB·인증·실제 .env는 수정하지 않았다.

기존 계약은 그대로 사용한다:

```text
GET /api/routes/graph?from=<출발지>&to=<목적지>&arrive=<시간대 포함 ISO 도착시각>
```

```json
[
  {
    "routeId": "recommend",
    "points": [
      { "departTime": "2026-11-15T07:30:00+09:00", "durationMin": 35 },
      { "departTime": "2026-11-15T07:40:00+09:00", "durationMin": 38 }
    ]
  }
]
```

위 숫자는 계약 설명용 예시다. 실제 교통 예측이 아니다.

백엔드 합의 요청사항:

1. routeId는 동일 검색의 GET /api/routes 응답 id와 정확히 일치하는 문자열이어야 한다.
   실제 모드는 recommend/time/distance/free 등이며 예시 fixture는 route-1/2/3이다.
   중복 경로를 합친 카드의 최종 id에 맞춰 반환한다.
2. 유효한 시간대 포함 ISO departTime, 유한한 0 이상 숫자 durationMin, 경로별 points 배열을 반환한다.
   해당 경로 그래프가 없으면 빈 배열 또는 해당 항목 생략을 사용한다.
3. 권장 출발시각 전후의 구간/샘플 간격을 합의한다. 권장 시간은 카드 departTime을 사용한다.
4. 동명 장소와 선택 좌표가 있을 때 from/to만으로 동일 경로를 재현할 수 있는지 확인한다.
   필요하면 fromLat/fromLng/toLat/toLng, routeIds 또는 검색 식별자 확장을 함께 명세화해야 한다.
   현재 프론트는 미합의 필드를 임의 전송하지 않는다.
5. 외부 API 호출량·쿼터·캐시 정책은 서버 담당자가 결정한다. 카드마다 재조회하지 않도록 전체 경로를 한 번에 반환한다.
6. 기존 오류 계약 4xx/5xx + {message} 유지. 지도/카드용 /api/routes와 독립된 실패 처리가 필요하다.

API 필드/Mock 계약은 변경하지 않았으므로 docs/api-spec.md나 fixture 자체를 수정하지 않았다.
프론트엔드 범위 안의 이 문서에 요청사항을 남겼다.

## Mac VS Code 실행과 웹에서 확인

새 VS Code 창으로 /private/tmp/gilit-duration-graph 폴더를 연다.
터미널에서 다음을 실행하면 저장된 config.js를 바꾸지 않고 예시 데이터만 보여 주는 서버가 열린다.

```sh
cd /private/tmp/gilit-duration-graph
python3 frontend/tests/serve-duration-preview.py --port 5502
```

http://127.0.0.1:5502/pages/search.html 에서 김해시청 → 동의대학교를 검색한다.
도착 날짜/시각은 미래(예: 내일 09:00)로 입력한다. 결과 화면 지도 아래 그래프를 확인한다.
카드를 전환해 그래프 색상·권장 시각·데이터가 바뀌는지 확인한다.
데이터 지점 hover/터치, Tab/방향키, 데이터 표를 사용해 수치를 확인할 수 있다.
포트 사용 중이면 이미 켠 예시 서버를 사용하거나 --port 5503으로 실행한다.

이 예시 서버는 실제 교통 API를 사용하지 않는다. JavaScript 지도 키가 비어 있으면
기존 SVG 좌표 미리보기가 표시된다. 기존 로그인 작업의 키는 이 worktree로 복사하지 않았다.
기존 8003 서버는 원래 로그인 작업 폴더를 제공하므로 새 그래프 변경은 5502에서 확인한다.

일반 설정 그대로 확인하려면:

```sh
python3 -m http.server 5503 --bind 127.0.0.1 --directory frontend
```

일반 정적 서버는 /api를 제공하지 않는다. 실제 검색/지도를 사용하려면 백엔드와 같은 출처로
이 worktree의 frontend를 제공하는 통합 환경이 필요하다. 백엔드 담당자에게 구성을 요청한다.
실제 모드에서 GRAPH_API_ENABLED=false이면 그래프만 연동 대기 문구가 나온다.

## 테스트 결과와 남은 확인

Node.js가 설치된 Mac에서 추가 npm 패키지 없이 실행한다:

```sh
node frontend/tests/duration-graph.test.mjs
node frontend/tests/search.test.mjs
node frontend/tests/map.test.mjs
node frontend/tests/routes.test.mjs
```

실제 작업 환경의 셸에는 node가 없어 제공된 Node REPL에서 위 테스트 모듈을 실행했다.
모두 통과했다. 미리보기 서버도 HTTP 200, 응답에서만 Mock 전환, 예시 3개 경로 제공, 원본 설정 보존을 확인했다. 새 테스트 범위:

- 불규칙 시간의 X축 비례/분 단위 Y축, 권장선 좌표 및 범위 밖 처리
- 빈 데이터/단일 지점/오류 날짜/음수/문자열/NaN/Infinity/정렬/중복
- KST 자정/연말/시간대 없는 입력, routeId 불일치·중복 및 fixture 연결
- 모의 DOM의 SVG, hover·터치 클릭·키보드, 데이터 교체, HTML 이스케이프
- API 비활성 시 무호출, 활성 URL, 요청 실패·10초 제한·취소
- 결과 화면 모의 DOM의 카드 전환과 지도/그래프 ID·색상·권장 시각 일치
- 늦은 그래프 응답 후 선택 경로 유지, 그래프 실패 뒤 지도 유지
- 기존 검색·지도·경로 회귀 및 변경 JS 문법 검사

모바일/태블릿/데스크톱 CSS는 구현했다. 실제 브라우저 검증은 Chrome 탐색 연결 오류와
사용자 브라우저 전환으로 완료하지 못해 시각 검증·실기기 터치는 미검증이다.
실제 그래프 API, 교통 예측 정확성 및 이 브랜치에서의 카카오 지도 타일 표시는 미검증이다.
테스트 통과나 예시 그래프 표시는 실제 교통 API 연동 성공을 의미하지 않는다.
