# SFR-001 프론트엔드 구현 및 연동 인계

프론트: 양해민 / 백엔드: 주인경. 작업 브랜치 haemin/login.
백엔드, DB, 서버 보안 및 실제 환경변수는 수정하지 않았다.

## 기존 상태와 변경

기존 이메일 회원가입/로그인 검증·모달·헤더·보호 페이지는 재사용했다.
기존 소셜 버튼의 임의 사용자 저장을 제거했다. 소셜 로그인 Mock 성공은 제공하지 않는다.
기존 gilit:user 캐시는 인증 근거로 읽지 않는다. 실제 모드에서는 페이지 진입 시
GET /api/auth/me 응답으로만 세션 상태를 복원한다. 이메일 Mock은 기존 계정 저장을
유지하며 gilit:mock:session(sessionStorage)에 개발용 상태를 별도 저장한다.

로딩/중복 클릭 차단, 취소·실패 안내, 기본 이름, 헤더·로그아웃 상태 갱신,
보호 화면 진입 전 세션 확인, 내부 페이지 복귀 검증을 추가했다.
실제 로그아웃 실패 시 성공한 것처럼 표시하지 않고 재시도를 안내한다.
모달 최대 크기·스크롤은 기존 스타일을 유지하고 모바일 헤더에 반응형 규칙을 추가했다.

## 연동 대기 및 주인경 팀원 요청사항

현재 docs/api-spec.md에 소셜 시작/콜백 경로가 없고 백엔드 인증 라우트가 확인되지 않는다.
아래는 **제안이며 확정 또는 구현된 API가 아니다**. 합의 후 docs/api-spec.md 갱신은 별도 요청한다.

| 요청 | 제안 계약 |
| --- | --- |
| Google 인증 시작 | GET /api/auth/google/start → 제공자 인증 화면 302 |
| 카카오 인증 시작 | GET /api/auth/kakao/start → 제공자 인증 화면 302 |
| 제공자 콜백 | 백엔드에서 경로 결정·등록, 코드 교환·state 검증·세션 생성 처리 |
| 프론트 복귀 | 성공 /index.html?auth_result=success, 취소 cancelled, 실패 failed |
| 사용자 조회(기존 명세) | GET /api/auth/me → 200 {id: 문자열, name, email, provider}; 미인증 401 {message} |
| 로그아웃(기존 명세) | POST /api/auth/logout → 세션/쿠키 만료, 204; 이미 로그아웃도 204 |

콜백 결과 쿼리는 표시용 신호이며 로그인 근거가 아니다. success여도 /me가 성공해야 로그인된다.
프론트 URL에는 code, 토큰, 비밀 값, 제공자 오류 원문을 전달하지 않는다.
첫 가입 약관 동의 시점·동의 화면 및 계정 중복 오류(기존 명세 409) 표시 계약도 합의가 필요하다.
현재 자유 형식 서버 오류 쿼리는 출력하지 않고 고정 실패 문구를 표시한다.

프론트와 /api는 같은 출처로 서비스하는 구성을 전제로 한다. 개발 시에도 동일 출처 프록시가 필요하다.
서버 쿠키·CORS·OAuth 보안 설정 및 프록시는 백엔드 담당자가 준비한다.
서버 기능 확인 후 frontend/js/config.js에서 USE_MOCK=false로 바꾸고,
SOCIAL_AUTH_START_URLS의 google/kakao에 합의된 같은 출처 /api/ 경로를 입력한다.
USE_MOCK는 기존 즐겨찾기·통계 모드에도 영향을 주므로 통합 환경에서 전환한다.
장소/경로 모드 USE_MOCK_ROUTES는 변경하지 않았다.

원래 페이지는 같은 탭 sessionStorage에 저장해 복귀한다. 허용된 사이트 HTML 경로만 사용한다.
쿼리와 해시는 보존하되 auth_result는 제거한다. 저장소 차단 시 인증 시작 실패를 안내한다.

## 개발자 콘솔 확인

- Google: 웹 애플리케이션 OAuth 클라이언트, 동의 화면·테스트 계정/공개 상태,
  백엔드와 합의한 개발·운영 콜백 URI의 정확한 일치 확인.
  https://developers.google.com/identity/protocols/oauth2/web-server
- 카카오: 카카오 로그인 활성화, 개발·운영 Redirect URI와 필요한 동의항목 확인.
  이메일/이름이 없을 수 있으므로 필수 사용자 정보 및 추가 동의 처리는 백엔드와 합의.
  https://developers.kakao.com/docs/ko/kakaologin/prerequisite
- OAuth 콜백은 백엔드 주소다. 프론트 /index.html 복귀 주소와 혼동하지 않는다.
- 프론트 코드에 Client Secret/REST 비밀 키를 넣지 않는다. 기존 지도 KAKAO_JS_KEY는 별도 용도다.
- 이 구현은 OAuth JavaScript SDK를 사용하지 않는다.

## Mac VS Code 실행

프로젝트 루트 터미널에서:

```sh
python3 -m http.server 5500 --bind 127.0.0.1 --directory frontend
```

http://127.0.0.1:5500/index.html 접속. Live Server를 쓸 때도 frontend가 서버 루트여야 한다.
현재 USE_MOCK=true: 이메일 회원가입/로그인만 개발용으로 시험하고 소셜 버튼은 연동 대기를 안내한다.
정적 서버에는 /api가 없으므로 실제 장소 검색·지도·인증까지 검증하려면 별도 통합 서버가 필요하다.

Node.js가 설치된 환경에서 추가 npm 패키지 없이:

```sh
node frontend/tests/auth.test.mjs
node frontend/tests/search.test.mjs
node frontend/tests/map.test.mjs
node frontend/tests/routes.test.mjs
```

## 검증 기록 (2026-11-14)

- 기존 검색·지도·경로 테스트 통과. 해당 기능 코드는 수정하지 않았다.
- 인증 단위 테스트: 사용자 캐시 불신, 세션 401/네트워크 오류, 이름 기본값,
  중복 이동 차단, 내부 복귀 검증, 성공/취소 콜백 모의 응답, Mock 성공 위조 차단,
  소셜 연동 대기 및 시작 URL 검증 통과.
- 모의 DOM: X/배경/Esc 닫기, 폼 로딩·중복 제출·오류 복구,
  보호 페이지 대기/표시/로그아웃 이동, 헤더 상태·이름 누락·HTML 이스케이프 검증.
- 셸에 node 실행 파일이 없어 제공된 Node REPL에서 테스트 모듈을 실행했다.
- Chrome 제어 연결 오류로 실제 브라우저 클릭·렌더링·모바일/데스크톱 시각 검증 미실시.
- 실제 Google/카카오 인증, 실제 세션 쿠키·로그아웃, 첫 가입·동의, 제공자 취소,
  실제 지도/장소 검색 연동과 OAuth 후 내부 페이지 복귀는 미검증. API 연결 뒤 통합 테스트 필요.
- 성공 콜백 테스트는 서버 응답을 모의한 테스트이며 실제 소셜 인증 성공이 아니다.
